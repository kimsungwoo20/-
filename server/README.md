# 연결 중개 서버

개미 RTS 온라인 대전용. 게임 계산은 **방장 브라우저**가 하고, 참가자는 방장과 **브라우저끼리 직접(WebRTC)** 연결한다.
이 서버는 처음 연결할 때 서로의 연결 정보만 전달하고, 판이 시작된 뒤에는 거의 쓰이지 않는다(게임 데이터가 지나가지 않는다).

## 실행

```
npm install
PORT=9080 node signaling.js
```

## 게임에 연결

- 배포한 주소가 `wss://내서버주소` 라면 게임 주소 끝에 `?signal=wss://내서버주소` 를 붙인다.
  예: `https://kimsungwoo20.github.io/-/play/?signal=wss://내서버주소`
- 또는 `godot/scripts/lobby.gd` 의 `DEFAULT_SIGNAL` 에 주소를 적고 웹 버전을 다시 빌드하면 주소를 붙이지 않아도 된다.
- GitHub Pages 는 https 이므로 서버도 https/wss 여야 한다(브라우저가 섞인 연결을 막는다).

## 배포

WebSocket 을 지원하는 Node.js 호스팅이면 어디든 된다. 무료 요금제가 있는 곳도 많지만 조건(잠자기, 월 사용량 등)이 자주 바뀌므로 고를 때 확인한다.
무료 요금제의 "일정 시간 요청이 없으면 잠드는" 서버는 첫 방 만들기가 수십 초 늦을 수 있다.

## 한계

- 방장이 나가면 판이 끝난다(방장 이전 없음).
- 일부 회사·학교망처럼 브라우저끼리 직접 연결이 막힌 곳에서는 접속이 안 될 수 있다. 이때는 중계(TURN) 서버가 필요하고, 중계를 거치는 데이터만큼 비용이 든다.
